## 6. Anomalies

**A1. The Commons digest window skips the previous session's announcements after a clean run.
This is a defect, it affects S0, and it is not a hash input.**

- **The timing.** NSE announcements for day D reach L1 at **00:30 IST on D+1**. The
  `announcements_capture` job logged `logical_date=2026-11-11 rows=525` at 2026-11-12 00:30:02,
  which is after that session's 22:00 M17 run.
- **The window.** `digest_new_filings` opens its window at `resume_after()`, the last clean run's
  session, and keeps filings knowable in `(since, session]` (`analyst/commons/digests.py`, about
  lines 963–982).
- **What happened on 12 Nov.** 11 Nov was the first clean run (0 failures), so the 12 Nov window was
  `(11-11, 11-12]`:
  - 11 Nov's 525 announcements were excluded, because they are dated 11-11;
  - 12 Nov's 987 had not landed yet.
- **Logged result.** `commons.digest.run cached=0 digested=0 filings=0 since=2026-11-11`.
- **Why earlier sessions were not hit.** Every one of them followed a run with at least one failure,
  so its window opened about a week back and covered D−1.
- **The effect on 12 Nov.** Round 0 showed no new filing digests. Deep-dive dossiers were not
  affected, because the on-demand path has its own lookback and digested 13 + … filings that night.
- **Tonight.** 12 Nov was clean too, so tonight's window is `(11-12, 11-13]`. It will drop 12 Nov's
  987 announcements, and the same will happen after every clean night until this is fixed.
- **The fix.** Open the window one session before the last clean run's session. Already-digested
  filings are cache hits, so the overlap costs nothing.
- **Hashes.** `digests.py` is Commons code and not a `mandate_hash` input, so no hash changes.
  Pre-registration §7 allows a Commons fix mid-window, journaled with the range of sessions it
  affected.

**Recommendation.** Approve S0 for tonight and authorise this small window fix, with a test that fails if it is reverted, to
land before 21:30 IST. If it does not land, S0 runs anyway and the gap is journaled under §7 from
S0. The other route is to land the fix first and start S0 on Mon 16 Nov. That costs one session and
changes no manager.

**A2. The participation rail cannot price an exit from a name moved to trade-to-trade.**

- **The name.** Onward Technologies (`INE229A01017`) moved from the NSE `EQ` series to `BE` on
  26 Oct, and still trades ₹0.6–2.4 cr a day on BE.
- **The refusal.** Every session, both `FM-SWING-EVT` books decided to SELL it, and the
  PARTICIPATION rail refused: "no 20-session median traded value … (11 → 7 session(s) knowable),
  limit 0". The rail's median counts EQ bars only, so the knowable count falls by one each session.
  The position cannot be exited while the name stays in BE.
- **What it affects.** Only the dry books hold it. The S0 books open on fresh capital, so they do
  not inherit it.
- **Why it matters.** It will recur for any live holding that moves to BE/BZ. It belongs with the
  owner-approved post-S0 item "total return after a trade-to-trade stint reinvests at the latest
  close in any equity series".
- **Hashes.** The rail's parameters are hashed and its traded-value input is not. A fix that reads
  the ISIN's traded value across equity series would change no hash.
- **Recommendation.** Fix it early in the window, journaled under §7.

**A3. A HOLD is voided when the model puts `stop_pct` on it: 47 of the 59 voids.**

- **The voids.** The decision contract voids a HOLD, TRIM or WATCH that carries `stop_pct` ("stop_pct
  belongs to a BUY; a held stop is tightened with new_stop_pct"). It recurs every session, most
  often in the POS books.
- **The other voids:**
  - 6 for a base-rate cell from a screen the name is not in;
  - 5 for an unknown citation;
  - 1 for a BUY stop outside 1.5–3 × ATR.
- **The safe default.** A voided HOLD changes nothing: the position stays and no order is staged.
  The contract fails safe.
- **The voided exits.** On 9 and 11 Nov a `FM-SWING-BRK` SELL of `INE934S01014` was voided for
  its base-rate cell, and on 9 Nov an EVT TRIM of `INE901L01018` was voided for `stop_pct`. So
  those exits did not happen.
- **Why not fix it before S0.** Fixing it means a prompt or contract change. That changes every
  manager hash and would restart the five-session count, so it is **not** recommended before S0.
  It is recorded as measured behaviour of these managers. The scoreboard's "voided decisions" line
  will show it over the window.
