## Box 1 — Hand-computed reference case reproduced exactly — **PASS**

*Box text:* "Hand-computed reference case (3 stocks, 5 years, SIP, one split + one merger + one
demerger) reproduced exactly."

**Evidence — the test drives the real accounting stack and matches literals to the paisa:**

```
$ uv run pytest tests/golden/test_reference_case.py -q
............                                                             [100%]
12 passed
```

- **3 stocks, 5 years, monthly SIP:** `instalment_dates()` yields 60 instalments, first
  2021-05-01, last 2026-04-01, strictly monthly — asserted by
  `test_the_sip_runs_a_full_five_years_of_monthly_instalments`.
- **Split:** IRCTC 1:5 (face value 10→2). 60 pre-split shares × 5 = 300, grows to 3,000;
  `test_the_split_multiplied_a_held_quantity` proves the ×5 is actually applied
  (`60 + 54×50 = 2,760` without the split vs. `3,000` with).
- **Merger:** HDFC Ltd → HDFC Bank at 42:25. Acquired ISIN emptied (`position(HDFC_LTD) is None`),
  675 × 42/25 = 1,134 converted into the survivor + 33×40 bought = 2,454
  (`test_the_merger_converted_the_acquired_holding_and_emptied_its_isin`).
- **Demerger:** RIL → JFS 1:1, 10% of RIL basis carved into JFS
  (`jfs.cost_basis == Decimal("135161.919")` = 1,351,619.19 × 0.10), a new ISIN created
  (`test_the_demerger_created_a_new_position_from_the_parents_basis`).
- **Literals, not engine output:** expected values are plain `Decimal` literals in
  `tests/golden/reference_case/expected.py` with the arithmetic shown line-by-line (cost of one buy
  across four rate regimes, month counts, quantities, cost bases, XIRR). Verified by
  `test_expected_values_are_plain_decimal_literals`. Final hand-computed XIRR literal
  `0.07739877` matches the real `backtest.xirr` output.
- **Real engine, not a mirror:** `build_reference_book()` (`scenario.py`) posts fills through the
  real `backtest.accounting.PortfolioBook`, prices every buy with the one shared cost model
  (`execution.costs`, invariant #4), and applies CAs via `apply_split`/`apply_merger`/
  `apply_demerger`. Confirmed by reading the source.

**Caveat (stated, not disqualifying):** the reference case pins *accounting* — cashflows,
quantities, costs, CA arithmetic, XIRR. Per its own docstring it uses (a) round representative
reference price levels "in the neighbourhood of the real prices" rather than real historical
closes, and (b) fill = reference level with zero slippage (slippage is exercised separately by
M4.8's SimBroker path). The load-bearing, independently-verified facts are the CA *ratios*
(1:5, 42:25, 1:1), drawn from the M2 golden CA suite. This is a legitimate and explicitly
documented modelling choice for a hand-computable reference; it is not a stub of the engine.

## Box 2 — Naive momentum backtest runs end-to-end 10 years — **PASS**

*Box text:* "naive momentum backtest runs end-to-end 10 years."

**Evidence — the exact M4.10 verify command, run live:**

```
$ uv run python -m backtest.run --policy naive_momentum --from 2016-04-01 --to 2026-03-31 --report
...
replay.complete digest=097e8e57da88efd0cd8d50247bafb36781806c1addbdca59e66062092a569475
               entries=5271 first=2016-09-02 last=2026-03-30 sessions=2364

  costs ₹86,580.55; journal 5271 entries
  report written to ops/gates/M4-momentum-report.md
```

Wall clock for the whole invocation: ~63s (engine replay ~43.5s).

- **Completes end-to-end with a full journal:** 2,364 sessions, 115 monthly rebalances, 5,271
  journal entries (1,079 BUY · 1,930 SELL · 2,262 HEARTBEAT — a heartbeat every no-op session,
  invariant #9). No `PitError` raised during the run (a look-ahead read would have failed it).
- **Reported against a benchmark with costs and runtime:** `ops/gates/M4-momentum-report.md`
  records final NAV ₹2,646,258.25, portfolio XIRR 10.69% vs benchmark 7.86% (costs included in
  every fill: ₹86,580.55 total), runtime 43.5s.
- **No tuning; parameters stated a priori:** top-N 20 equal-weighted, monthly rebalance, trailing
  12-month total-return signal, ₹1,000,000 opening capital, 0.98 buy budget — listed in the report
  under "chosen a priori — no tuning was performed."

**Caveats (stated in the report and confirmed here):**
1. **Window is ~9.6 calendar years, not a full 10.** Requested `--from 2016-04-01 --to 2026-03-31`;
   actual replay ran 2016-09-02 → 2026-03-30 because that is the span of the L1 store. The run is
   end-to-end over the full available history, which is the box's intent (engine validation over
   full history), but it is not a literal 120-month calendar decade.
2. **Benchmark is an L1-derived proxy, not the licensed NSE NIFTY-TRI.** Equal-weight average of
   the 50 most-liquid names, seeded to 1000, flowing through the same `TriSeries`/
   `compare_to_benchmarks` code the real series will use. The 2.84% "excess" is not alpha.
3. **This L1 lake carries no corporate actions (adjusted == raw).** So the momentum run does not
   exercise CA-in-the-book on real data; that is what Box 1's reference case covers.

None of these defeat the box ("runs end-to-end 10 years") — the engine survives a full-history
replay with PIT scoping, shared costs, whole-share allocation, accounting and journaling all
intact — but they are the honest boundaries of what the run proves.

## Box 3 — PIT leak test passes — **PASS**

*Box text:* "PIT leak test passes."

**Evidence — the exact M4.11 verify command:**

```
$ uv run pytest tests/integration/test_pit_leak.py -q
......                                                                   [100%]
6 passed
```

The harness is genuine defence-in-depth, not a tautology (read `tests/integration/test_pit_leak.py`):

- **Guard catches an honestly-declared future read:** `FutureReachingPolicy` reads rows that carry
  real future `knowable_date`s; `PitContext.admit` raises `PitError`
  (`test_the_guard_stops_an_honest_future_reaching_read`).
- **Audit catches the deliberate mis-declared leak the guard cannot see:** `MisdeclaringPolicy`
  reads a dataset that lies — declares every future row knowable "today". The guard admits it; the
  replay-wide `PitAuditor` re-derives each record's *true* knowable date and flags every leaked
  datum, raising `PitLeakError` (`test_the_audit_catches_a_misdeclared_future_read`). This is the
  "add a deliberate leak in a test double and prove the harness catches it" requirement.
- **Proven non-redundant:** `test_the_audit_is_the_only_thing_that_catches_the_misdeclared_leak`
  shows the guard alone admits the mis-declared rows silently.
- **Anti-vacuity:** `assert_audited()` fails a run that read nothing; `test_the_replay_actually_traded`
  asserts real buys/holdings/ledger lines exist.

Offline and deterministic (in-memory PIT store + market, `FrozenClock`), as required for CI.
