### Reference A — yfinance cross-check (`tests/golden/test_yfinance_reference.py`, M2.7)

Yahoo's independently-compiled adjusted series for the `.NS` ticker, compared at each ex-date.

```
$ uv run pytest tests/golden/test_yfinance_reference.py -q -m 'not network'

```

- Fixtures are **real**, fetched from live Yahoo on 2026-09-02 via `yfinance` 1.5.2 and frozen under
  `tests/fixtures/yfinance/` (see `PROVENANCE.md`). Spot-checked: `irctc_split_2021.json` carries
  Yahoo split multiplier `5.0` at 2021-10-28 ⇔ our `price_factor` `0.2`; `ril_bonus_2024` `2.0` ⇔

**Caveat — reference A runs offline against frozen fixtures, not live network.** This is by design
(AGENTIC_CONTEXT B8: the test suite never hits the network). The live pull
(`test_refresh_fixtures_from_yfinance`) is the source of the 7 network skips and is opt-in via
`-m network`; it was exercised to produce the checked-in fixtures dated 2026-09-02 but does not run
in the gate command.

### Documented discrepancies — resolved

The other 6 skips are **not** unverified holes; they are the carve-out cases routed to a dedicated
resolution test:

- `jiofin_demerger_2023`, `tatamotors_demerger_2025`, `tatamotors_dvr_2024`: Yahoo's split/dividend-
  only model cannot represent a carve-out onto a different ISIN, so it records no action and does not
  bridge the break. `test_documented_disagreements` asserts (load-bearing, not decorative) that
  Yahoo carries a finite return across the ex-date while reference B bridges it (`ret=None`), and the
  `DISCREPANCIES` verdict is **reference B authoritative**. Our output is not bent to match Yahoo.

**Caveat — one verified reference-A gap.** `ltim_merger_2022` has no reference-A series: Yahoo serves
zero rows for `LTIM.NS` in this environment while peer large caps return in the same call. Rather
than fabricate a series, the fixture is an unavailability marker with a reasoned verdict (reference B
authoritative; a surviving-entity merger carries a unit price factor, so the hand-computed literals
stand). `test_reference_a_unavailable_is_documented` asserts the marker carries no fabricated rows
and its reason matches the verdict. So of the 7 named cases, 6 are cross-checked by both references;
LTIM is checked by reference B only, with the gap documented and handled per spec.

## Box 2 — A newly inserted CA correctly rewrites the ISIN's full adjusted history

**PASS.** (= M2.9 acceptance 2: "live CA-insertion retroactive rewrite demonstrated end to end")

### Full-history rewrite logic (M2.4)

```
$ uv run pytest tests/unit/test_factors.py -q
16 passed in 0.53s
```

`test_inserting_a_new_ca_rewrites_the_full_history_not_a_patch`: after an earlier bonus is
backfilled, the chain is rebuilt whole — the 2020 row's cumulative factor becomes `0.5 × 0.2 = 0.1`
(not a local patch), and both events are present. `test_recompute_writes_full_chain_and_one_l2_invalidation`
proves the recompute also queues exactly one L2 invalidation. (These use an in-memory fake
connection for the recompute logic.)

### End-to-end seam against real Postgres + DuckDB (M2.4 → M2.5)

```
$ uv run pytest tests/integration/test_l2_views.py::test_rebuild_invalidated_drains_only_flagged_isins -v
1 passed in 1.37s
$ uv run pytest tests/integration/test_l2_views.py -q
10 passed in 2.71s   (0 skipped — Postgres is up; the fixture skips only when it is unreachable)
```

`test_rebuild_invalidated_drains_only_flagged_isins` is the real seam: it inserts a reconciled CA
into the live `corporate_actions` table, runs `recompute_isin` (M2.4) which persists the factor chain
and records an open `l2_invalidation`, reads it back (`price_factor_asof(2021-06-01) == 0.2`), then
`rebuild_invalidated` (M2.5) materializes exactly that ISIN's L2 from L1 + persisted factors and
drains the queue — the control ISIN, never invalidated, gets no partition. L2-rebuild determinism is
separately proven by `test_wipe_and_rebuild_is_byte_identical` and per-ISIN incrementality by
`test_materialize_one_isin_leaves_others_untouched`.
