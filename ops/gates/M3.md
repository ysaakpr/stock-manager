## Box 1 — "Cross-exchange price sanity checker live"

**PASS.** (Owning task: M3.3.)

- The rule exists and is a first-class D7 sentinel rule, not a stub:
  `dataplatform/quality/rules/cross_exchange.py` defines `CrossExchangeRule` and self-registers via
  `register(CrossExchangeRule())` at module load. `dataplatform/quality/sentinel.py` carries an
  `exchange_closes` input surface the rule reads (NSE vs BSE raw close per ISIN/session), committed.
- `uv run pytest tests/unit/test_cross_exchange.py -q` passes. It proves both directions of the
  acceptance: a synthetic divergence flags under `cross_exchange_divergence`, matched prices do not.
- Thin-BSE-volume handling is real, not hand-waved: the rule down-weights / excludes low-liquidity
  BSE prints so a thin print is not treated as a data error ("must not cry wolf" per M3.3 spec), and
  the rationale is documented in the module. Tests cover the thin-volume exclusion path.
- Comparison is on **raw** L1 closes (invariant #3): the rule deliberately does not compare adjusted
  series, so a cross-exchange adjustment gap is exactly what it is able to notice.

Caveat: exercised on synthetic/frozen fixtures (B8 — the suite never touches the network). The rule
is live in code and registered; it has not yet been run against a live production divergence.

## Box 2 — "Flows queryable 10 years back where sources permit"

**PASS as written — with a load-bearing honesty caveat.** (Owning tasks: M3.4 FII/DII; M3.5
bulk/block deals; adjacent: M3.6 shareholding.)

The box's own qualifier is "where sources permit," and M3.4's acceptance explicitly requires: "if
depth is shorter, record the real depth in the source register rather than claiming 10y." That is
exactly what was done, so the box passes on its literal terms. But the honest depth must be stated
plainly for any downstream consumer:

**FII/DII (`nse_fii_dii_flows`, source register):** depth is **one session, accruing forward** — NOT
ten years. The register records this as *measured*, not inferred:

```
history:
  measured_at: 2026-08-08T19:32:00+05:30
  sessions_available: 1
  earliest_available: 2026-08-07
  latest_available: 2026-08-07
  accrues_forward: true
```

The endpoint (`/api/fiidiiTradeReact`) serves only the latest session, has no date parameter (a
`?date=` is silently ignored — same 215 B, same sha256), and a missed day is a permanent hole. The
register names the real fallback for the FII leg (NSDL FPI portal + CDSL series — FPI-only, no DII
side, custodian-confirmed basis) but explicitly scopes its ingestion out of M3.4. **"10 years back"
is not achievable from this source and the register does not claim it.**

**Bulk & block deals (`nse_bulk_deals`, `nse_block_deals`):** rolling current-session CSVs, not
date-parameterised — captured daily and keyed on the Date column. History likewise accrues forward
from go-live; no deep backfill exists from these URLs. Verified live (bulk 200/10,687 B; block
200/250 B — a genuinely quiet one-deal day, which the register warns the quality layer not to treat
as a failure). `test_deals.py` passes: ISIN resolution via D2 with raw client names preserved, and a
deal in a held ISIN queryable by `(isin, date)` for T0.

**Shareholding (`nse_shareholding_pattern`):** carries both `(period_end, filing_date)` with neither
inferred from the other, promoter pledge % as a first-class field, and a PIT test proving a query
before `filing_date` cannot see the row (invariant #7). `test_shareholding.py` passes.

**Bottom line for box 2:** the plumbing is correct and queryable; the *depth* is honestly ~nil at
source today and grows forward. Any consumer that assumes a decade of flow history exists is wrong.
