# M15.6 — Postgres and the status API bound to 127.0.0.1 — gate note, 2026-10-08

## Finding

From the PR #90 review, confirmed on the host with `ss -ltn` and `docker ps` before this change:

```
LISTEN 0.0.0.0:5433   LISTEN [::]:5433    trading-platform-postgres-1  0.0.0.0:5433->5432/tcp, [::]:5433->5432/tcp
LISTEN 0.0.0.0:8000   LISTEN [::]:8000    trading-platform-app-1       0.0.0.0:8000->8000/tcp, [::]:8000->8000/tcp
```

Postgres runs with the dev-default credentials; the status API has no authentication. Host
iptables `INPUT` policy is `ACCEPT`, and docker's own chain is ahead of it anyway, so exposure
depended only on the cloud security group.

## Change

| File | What |
|---|---|
| `ops/docker-compose.yml` | `"127.0.0.1:${POSTGRES_HOST_PORT:-5433}:5432"`, `"127.0.0.1:${APP_HOST_PORT:-8000}:8000"`; header explains why the address is a literal, not a variable |
| `tests/unit/test_compose_ports.py` | parses every compose file in the repo; fails on a publish with no host IP, `0.0.0.0`, `::`, a non-loopback IP, or an IP from a variable. The parser is also run on bad specs (short and long syntax) so it cannot pass vacuously; run against the pre-change file it reports both ports |
| `ops/runbooks/loopback-only-ports.md` | what changed, consumers, ssh tunnel, post-merge recreate and checks, security-group advice |
| `ops/README.md` | ports table, loopback section, `curl 127.0.0.1:8000` |
| `ops/runbooks/fundamentals_backfill.md` | `curl` uses `127.0.0.1:8000` |

No env var for the bind address: no consumer is off-host, and an override is one `.env` line from
`0.0.0.0`.
