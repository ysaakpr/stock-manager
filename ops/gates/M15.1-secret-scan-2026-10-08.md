## Scanner choice: detect-secrets 1.5.0, through uv

- **Installable without root, pinned, one toolchain.** It is a Python package: a dev dependency in
  `pyproject.toml`, hash-pinned in `uv.lock`, installed by the same `uv sync --frozen` CI and every
  worktree already run. gitleaks (the main alternative, better at history scanning) is a Go binary:
  it would need a separate download-and-checksum step in CI, in every worktree and on the box, and a
  test that needs it would have to skip when it is absent — a gate that can skip is not a gate.
- **History coverage closed in the wrapper**, which was gitleaks' advantage: `--commits RANGE` walks
  every commit of the range and scans each commit's added/changed blobs at that commit plus its
  message. A secret added in one commit and deleted in the next is caught (the 2026-08 attempt at
  this gate recorded exactly that as an accepted known gap).
- **No network at scan time.** detect-secrets can "verify" a match by calling the provider (and it
  imports `requests` for that). The wrapper removes `is_ignored_due_to_verification_policies` from
  the settings on every run, whatever the baseline says; the baseline is generated with `-n` too.
  Verification is also wrong for a leak scanner: a planted fake or an already-revoked key "fails"
  verification and would be hidden.

## The wrapper (`ops/secret_scan.py`) and why it exists

Stock `detect-secrets-hook` was not enough, for four concrete reasons found while building this:

1. **Silent pass with zero plugins.** detect-secrets' own `cache_bust()` resets the settings just
   loaded from the baseline; scanning after it logs `No plugins to scan with!` and reports *clean*.
   The wrapper clears only the derived caches and **refuses to run (exit 2)** if any of
   KeywordDetector, TokenAssignmentDetector, BasicAuthDetector, AWSKeyDetector, PrivateKeyDetector is
   missing — `test_baseline_without_a_required_detector_is_a_config_error`.
2. **Baseline matching by absolute path.** `PotentialSecret.filename` holds the root-joined path, so
   the library's own set subtraction never matched a baseline entry when scanning with a root. The
   wrapper compares on (repo-relative path, value hash, detector).
3. **No "token" keyword.** The stock KeywordDetector list has `api_?key` and `secret` but not
   `token`, so `KITE_ACCESS_TOKEN=<value>` passed. `ops/secret_scan_plugins.py` adds
   TokenAssignmentDetector (access/refresh/request/session/bearer/auth/api/bot `_token` assignments,
   value ≥16 chars with a letter and a digit) and AnthropicKeyDetector (`sk-ant-…`).
4. **Unsafe baseline update.** `detect-secrets scan --baseline B FILE` rewrites B with only FILE's
   results, dropping every other entry. `--accept FILE` appends that file's findings only.

It also ignores inline `# pragma: allowlist secret` (an allowlist entry nobody reviews) and never
prints a matched value — findings are `path:line: detector`.

## Proof (tests/unit/test_secret_scan.py)

12 test functions, 22 collected cases. All planted values are built at runtime from fragments and
sha256 output, and the test file itself scans clean.

- Exit 1 on each of: Kite `KITE_API_KEY = "…"` (py); `kite_api_secret = "…"` (py);
  `KITE_API_SECRET=…` (.env); `access_token = "…"` (py); `KITE_ACCESS_TOKEN=…` (.env);
  `access_token: …` (yaml); Postgres DSN with password (py and .env); `AKIA…` AWS key; an RSA private
  key header; an Anthropic key in prose. Each asserts the value is absent from the scanner's output.
- Exit 0 on a clean file with realistic `SecretStr` / `os.environ` / sha256 lines.
- Commit message: finding → 1, clean → 0. Inline pragma cannot silence a finding.
- `--staged` scans the index: staged secret → 1; staged clean but secret on disk → 0.
- `--commits`: secret added then deleted — final tree clean (0), last commit alone clean (0), range
  including the add → 1. A secret in a commit message in the range → 1.
- `--accept` appends only, and pins to file + value: the same DSN in another file, or a new token in
  the accepted file, is still a finding.
- `make -n check`'s first command is the scan; hooks are executable and call `--staged` /
  `--message`; ci.yml has `fetch-depth: 0` and the `--commits` step.

Command: `uv run pytest tests/unit/test_secret_scan.py -q` → 22 passed.
