# M15.2 — Disclosure text in the T1 evidence bundle

**Task:** M15.2 (real-money readiness item b; closes the code half of BACKLOG `M6.8 (F1)`) ·
**Measured:** 2026-10-08 08:47 IST, against this machine's lake (`data/L1/announcements`) and
production Postgres · **No network fetch, no model call.**

## What changed

The M6.8 drill built its T1 bundle from the T0 flag alone, so T1 saw only "Resignation of
Auditor". There was no production path that put the triggering disclosure into the bundle.
There is one now:

- `analyst.monitor.request_for_escalation(escalation, thesis=, announcements=, as_of=)` builds the
  `BundleRequest` for a T0 escalation. It reads the holding's disclosures from the same in-memory
  `AnnouncementIndex` that the daily job builds from L1 and T0 sweeps.
- `analyst.monitor.select_disclosures` keeps only rows with `ts <= as_of`, the decision's tz-aware
  as-of instant, not merely its date. It looks back 30 days and takes the newest rows first.
- `BundleBuilder` renders each disclosure as its headline, followed by one of:
  - `text: …`
  - `text_unavailable: <reason>`
  - `attached document: text not captured (<attachment_ref>)` when the filing links a document.

  The evidence item's `detail` records `text_status`, `text_unavailable`, `text_truncated`,
  `text_original_chars` and `document_text`.

### Bounds (`DisclosurePolicy`, default `DEFAULT_DISCLOSURE_POLICY`)

| Bound | Default | What happens past it |
|---|---|---|
| characters per disclosure | 2,000 | truncated, ends `[…truncated]`, `text_truncated: true` |
| characters across the bundle | 8,000 (about 2,000 tokens at 4 chars/token) | the overflowing disclosure keeps its headline and is marked `text_unavailable: bundle_text_cap` |
| disclosures per bundle | 8 | the oldest are not selected |
| lookback | 30 days | the window opens 30 days before the as-of date |

The bundle's existing 12,000-token budget (`DEFAULT_BUDGET`) still applies on top of these caps.

### `text_unavailable` reasons

| Reason | Meaning |
|---|---|
| `no_body` | the exchange feed carried no text |
| `headline_echo` | the feed text says nothing beyond the headline once NSE's "<Co> has informed the Exchange about/regarding" lead-in and filler words ("of the company") are removed |
| `bundle_text_cap` | the per-bundle character cap was already used up by newer disclosures |

## What this does and does not fix

The bundle now carries all of the disclosure text the platform has. It also says plainly when it
has none: a headline is never presented as if it were text.

What the platform has is NSE's `attchmntText`, a one-line summary with a median length of 137
characters. The drill's richer case, a mid-term resignation that cites unverifiable related-party
transactions, lives in the attached PDF, and **no PDF is captured** for any announcement. So for
the 27% of disclosures that are headline echoes, including most "Change in Auditors" filings, T1
still cannot tell a rotation from a resignation. It is now *told* that it cannot.

Closing that gap means capturing the PDF text in the announcement capture job, not in the decision
path. That job is the follow-up below. Until it runs, a T1 EXIT on a `headline_echo` disclosure is
still a headline-driven decision. M8 should treat it as needing a human.

## How it is verified

`tests/unit/test_disclosures.py` (22 collected cases from 19 test functions):

- **Drill shape.** The real `T0Monitor` sweeps an index that holds a resignation disclosure. The
  bundle built the old way, from the flag only, lacks the text. The bundle built by
  `request_for_escalation` contains `text: <body>`. A missing body renders
  `text_unavailable: no_body`.
- **PIT.** A disclosure exactly at `as_of` is included, and one a second later on the same day is
  excluded. Three mutations of `row.ts <= as_of` were each checked to fail a test:
  - `>=` (inverted)
  - the filter removed
  - `<` (strict)
- **Builder refusal.** The builder refuses a disclosure dated after the trading date.
- **Bounds and reasons.** Truncation, the bundle cap, `max_items`, and the echo, filler-echo, no-body
  and attachment cases each have a test.
- **Determinism.** The same inputs produce byte-identical `canonical_bytes`.
- **No settings.** Neither `disclosures.py` nor `bundle.py` imports `dataplatform.config`,
  `Settings` or `os`.

`tests/integration/test_fire_drill.py` now builds the drill's T1 bundle through
`request_for_escalation` and asserts that the text is in the prompt. Its result was 8 passed and 6
`live` tests deselected, so no model was called.
